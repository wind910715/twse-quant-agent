## 2. 假設

- H1（H2 缺口的機制）：程式版唯一的擋下角落是「0050 跌破月線 1.2% 且個股 20 日漲幅 < 3%」，
  這個角落恰好集中在**回檔日**——而回檔日正是 S1 破底翻（買被打下去的股）與 S0 VCP 收斂
  最常發訊號的日子。在多頭半段（H2），回檔是買點不是轉勢，程式版在那幾天把弱勢股全擋掉，
  等於把 S1／S0 的進場機會擋在門外，參與度不足，複利跟不上 0050。
- H2（弱市的反面）：程式版在確認空頭時仍放行任何 20 日漲幅 ≥ 3% 的個股；
  空頭確認後弱勢股的假突破多、勝率低，應收緊到只放真正的強勢股。
- H3（動態而非固定線）：同一條「跌破 MA20 1.2%」在 MA20 上行時是回檔、在 MA20 下行時是轉弱，
  固定一條線無法區分；用 **MA20 的 5 日斜率**區分兩者，閘門嚴格程度隨狀態動態調整。
  斜率取 5 日：MA20 變化慢，1 日斜率太 noisy，20 日斜率落後一個月才反應轉勢。

## 3. 動態規則全文（凍結，只用訊號當下已知資料，不得前視）

輸入（皆為訊號日收盤已知）：
- `d = 0050 收盤 / 0050 MA20 − 1`（0050 與 MA20 的距離）
- `m = 0050 MA20 / 5 個交易日前的 MA20 − 1`（MA20 的 5 日斜率）
- `s = 個股 20 日漲幅`

| 狀態 | 條件 | 閘門 |
|---|---|---|
| 強勢回檔 | `m > 0` 且 `-0.05 ≤ d < -0.012` | **全放行**（不論 s） |
| 弱勢確認 | `m < 0` 且 `d ≤ -0.03` | **加嚴：只放行 `s ≥ 0.08` 的股** |
| 其餘 | 以上皆非 | 沿用程式版原規則：`0050 收盤 < MA20×0.988 且 s < 0.03` 才擋 |

補充凍結細節：
- 強勢回檔設下限 `-0.05`：`d < -0.05` 即使 `m > 0` 也不放行（防崩盤第一天追跌；
  MA20 落後，暴跌初期斜率仍為正，下限把這種日子擋回原規則）。
- `m = 0`（含斜率輸入缺失）一律落入「其餘」，即程式版原規則。
- `d`、`m` 計算後四捨五入到小數 6 位，使文件邊界（-0.05／-0.03／-0.012）行為與字面一致，
  不受二進位浮點誤差影響（實測：`95/100-1` 在浮點下為 -0.050000000000000044，
  未四捨五入會使邊界 `d = -0.05` 誤判；見 §6 驗證發現）。
- 「其餘」分支的表示式維持原樣 `bench_close < bench_ma20 * 0.988`，與舊版逐位元相同。

## 7. 失效模式（事前寫明，跑完對照）

1. **回檔層放錯**：2016–2026 的回檔若多半延續成修正而非反彈，強勢回檔層放行的弱勢股
   會拖累勝率與 RR；屆時 (a)(b) 會直接反映，不得以「回檔層本意是參與」辯護。
2. **弱勢層過嚴**：`s ≥ 8%` 在確認空頭時可能幾乎無股可進，筆數 (e) 掉太多或 H1 參與度歸零；
   若 variant 筆數遠少於 baseline 且 (a)(b) 未明顯改善，代表加嚴的代價大於收益。
3. **斜率 noisy**：MA20 的 5 日斜率在盤整期可能頻繁翻正負，兩層反覆切換、行為接近原規則；
   若 variant 與 baseline 數字幾乎相同（Δ≈0），即為此模式，不得解讀為「規則無效」以外的結論。
4. **單一樣本過擬合**：門檻 -0.05／-0.03／0.08／5 日是事前凍結的經驗值，
   2016–2026 只有一組大多空循環；PASS 也只代表在此樣本相對 baseline 較優，
   不代表門檻本身是最優的，跑完不得再調門檻重測。
5. **0050 單一指數盲點**：閘門只看 0050；0050 平盤但中小型股強勢的盤面，閘門無法反映，
   此為規則先天限制，不在本變體處理範圍。
6. **採用附註**：若 PASS 且使用者拍板採用，`screener.py:296` 與 `futures_brk20_mapper.py:171`
   須在同一批修改中補傳 `bench_ma20_prev5`（機械性改動，與 backtest 同口徑），
   否則實盤與回測的閘門將不一致；本次變體不改這兩處（回測 harness 只走 backtest.py）。

  第 60 根後擋下列集合與舊守衛相同。
